# 一次情報データベース（Primary Info DB）

塔筋さんの現場知見・事例・お客様の本音を蓄積するデータベース。
記事執筆時にここから一次情報を引用する。

---

## DB構造

各エントリは以下の形式で記録する:

```
### [テーマ] Q&A-{連番}
**テーマ:** {テーマ名}
**質問:** {逆質問の内容}
**回答:** {塔筋さんの回答（原文ママ）}
**活用ポイント:** {記事のどの箇所でどう使うか}
**追記日:** {YYYY-MM-DD}
```

## 定着・離職防止

### [定着・オンボーディング] Q&A-001
**テーマ:** 新入社員の定着率を上げるオンボーディング設計
**質問:** 4月入社の新入社員が、最初の3ヶ月で「辞めなくて良かった」と感じた瞬間について、最近のお客様でエピソードはありますか？どんな関わり方や仕組みが効いていましたか？
**回答:** 人事と営業の目線が合っていなくて採用後のミスマッチパターンがある。効く仕組みとしては個別最適が多いですかね、人材育成に特効薬はないのですが上司を育てる、部下がこういうときどうする？などシーン別の対応を考えさせるのはよかった。
**活用ポイント:** 「上司育成とシーン別対応」を定着施策の核として紹介。人事と営業の目線のズレ→採用ミスマッチのメカニズム説明に使用。
**追記日:** 2026-03-22

**活用ポイント:** 「優しくすること＝逆効果」の逆説ポイントとして記事の冒頭フックに使用。事業目的からのズレという切り口でh2展開。

## 使用方法

### STEP 3でのチェック方法
1. テーマに対応するセクションを開く
2. Q&Aエントリが3件以上あればSTEP 4へ進む
3. 3件未満の場合は逆質問を生成して停止

### 新規エントリの追記方法
知見回答が入力されたら以下の形式でDBに追記する:
1. 該当テーマのセクションに新しいQ&Aエントリを追加
2. 連番を更新（最後の連番+1）
3. 回答は原文をなるべくそのまま記録
4. 活用ポイントを明記する

### 記事での引用ルール
- 事例は「【業種 職種 Aさん】」形式で架空の具体例として再構成
- 個人が特定できる情報は含めない
- 引用する場合はダブルチェック（STEP 6のReviewer Agentが確認）
